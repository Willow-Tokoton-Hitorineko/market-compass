# AI使用与验证记录

## 使用工具与参与环节

- Codex：题目与源码审查、前后端实现、接口适配、确定性计算、测试、代码审查及材料整理。
- DeepSeek：产品运行时生成结构化研究计划，依据已校验证据组织市场解释和后续研究问题。
- 扶摇金融数据API：交易日历、指数行情、宽基成分、行情快照、情绪股票池及行业样本数据。

提交者确定研究主链路、LIVE/SNAPSHOT模式、证据追溯及克制的页面方向，提供接口凭据，并实际操作产品验证分析生成和证据弹窗。具体代码实现、自动化测试和缺陷修复使用Codex辅助完成；以下记录不将工具执行的工作描述为提交者独立手写或逐项亲测。

## 设计决策与修正

1. 将纯静态SAMPLE展示调整为服务端在线研究与真实Snapshot；构造数据仅保留用于旧规则回归测试。
2. 停止把个股估值接口用于指数PE/PB；指数估值能力缺失明确显示。
3. 增加指数、区间和研究问题输入；模型生成任务顺序，服务端执行白名单取数任务。
4. 将维度级来源说明扩展为结论与证据ID、原始字段、计算输入、统计口径、时点及请求标识。
5. 置信度改为证据质量评估；状态条件与维度分类共用确定性规则。
6. 日历失败不回退服务器日期；盘中日线不当作完成收盘；过期日历不用于断言今日是否交易。
7. 模型异常、无效证据引用或越界解释明确拒绝；显示RULE降级。保存案例显示REPLAY。
8. 快照仅保留研究必要字段，排除完整个股报价、账户、持仓和真实凭据。

## 代码审查与回归验证

代码审查发现并修复四类问题：历史数据缺少来源时点仍被采信；短历史均值误标MA20；缺失基准被当作零计算行业相对收益；空均线参与比较导致主要矛盾误判。

修复后要求可靠来源时点和足够历史数据，缺失基准显示不可比较，历史不足不识别正常结构背离。回归断言覆盖5、19、20、59条日线及来源缺失、过期等情形。

增加中英文预测及交易建议拒绝检查，以及实例并发限制、日调用配额、重复请求合并和结果复用。调用保护不构成全站费用上限。
