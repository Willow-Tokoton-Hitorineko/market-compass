# 大势罗盘

面向A股研究的市场状态工作台。围绕「指数＋区间＋问题」组织取数、校验证据、解释主要矛盾，并给出判断可能改变的条件。

不输出未来涨跌预测、收益承诺、仓位或买卖建议。

已部署地址： https://tahoe-psychiatry-surrounded-task.trycloudflare.com

源码仓库：https://github.com/Willow-Tokoton-Hitorineko/market-compass

运行状态（2026-10-14）：原Sites地址在多个网络出口遭Cloudflare拦截，已改用独立临时演示入口。提交者已在此前失败的网络确认研究生成与证据窗口可用；在线计划、取数和解释也通过接口验证。该入口依赖提交者本机与网络转发进程持续运行，关机、休眠、断网或停止进程后不可用；不宣称其为永久托管。Vercel与Netlify适配器已准备，尚未部署。

产品按访客无需登录、安装或填写API Key设计。进入页面后选择指数和20/60个交易日区间，提出问题，点击「开始研究」。点击核心结论或主要矛盾核验证据；在结果底部继续研究风格、行业、风险变量和历史阶段。右上「案例回放」读取保存的真实模型研究结果。

## 本地启动

Node.js 22及以上（验证环境为24.15.0）。

```sh
npm ci
npm start
```

默认 http://localhost:8787 。若本机端口已占用，设置 `PORT=8788` 后启动。没有服务端凭据时，LIVE会明确失败并切换到真实SNAPSHOT，模型计划及解释显示规则降级。案例回放不需要任何远程服务。

```sh
npm test
npm run build
```

`npm test` 在隔离配置下运行45项测试，不调用付费模型。`npm run build` 生成 `sites/market-compass/worker/index.js` 和 `sites/market-compass/dist/`，并准备不含凭据的部署源码副本。

## 配置

复制 `.env.example` 为 `.env`，由项目所有者在本地或托管平台设置；评委无需配置。

- `FUYAO_API_KEY`：扶摇金融数据API凭据。
- `DEEPSEEK_API_KEY`：DeepSeek模型调用凭据。
- `AI_BASE_URL`：服务端模型地址，默认 `https://api.deepseek.com`。
- `AI_MODEL`：请求模型名，默认 `deepseek-chat`；页面记录服务实际返回的模型标识。
- `PORT`：本地端口，默认8787。

密钥只放本地忽略文件和Sites服务端Secret。源码、快照、前端资源和研究响应不包含密钥。

## 用户与产品选择

目标用户为需要复盘市场证据的投研人员。产品围绕一个核心研究闭环，避免把多个行情指标堆成信息看板。首屏直接开始；研究计划与执行状态可检查；证据默认折叠。

七维框架包括行情结构、市场宽度、风格轮动、估值、流动性、情绪、重要事件。当前5个维度有实际证据，指数估值与事件源明确缺失。FACT表示来源字段或确定性计算，SYNTHESIS表示归纳解释，UNCERTAINTY表示证据局限与不能确认的判断。

## AI角色

AI是Research Orchestrator：识别问题重点，排序研究任务，解释已验证证据、组织矛盾和后续研究问题。服务端按模型计划顺序执行白名单数据任务；指数参数由用户输入确定。共享行情请求在任务之间复用。

模型不负责算收益、均线、宽度、阈值和置信度。数值由代码计算。研究计划经过结构校验并以服务端HMAC签名；解释必须引用存在的证据ID。错误引用、越界文本、来源冲突或模型异常会拒绝模型解释并显式展示规则结果。没有展示内部思维链。

## 运行架构与模式

原生HTML/CSS/JS前端与Node研究服务；当前公网演示通过Cloudflare Quick Tunnel转发本机服务，前端同源调用API。服务端环境变量保存凭据。保留Sites Worker、Vercel与Netlify部署适配。

- LIVE：扶摇实时取数，核心日历或所选指数取数失败时明确切换SNAPSHOT；次要维度失败保留失败状态与缺失原因。
- SNAPSHOT：`data/snapshot.json` 为2026-10-13采集的真实数据，日期与原始值固定；仍可由在线模型研究。
- AI LIVE / RULE / REPLAY分别表示实时调用、规则降级、保存回放，与数据模式独立。

最多逐个上游任务取数，默认12秒接口超时；模型35秒超时。实例内3分钟行情缓存；每IP每实例每分钟8次研究API请求限制。实例缓存与限流非全局保障，生产扩容需持久化限流和预算管理。

## 数据与证据

来源：[扶摇金融数据API](https://fuyao.aicubes.cn/)，接口字段依据官方 `llms-full.txt`；本次使用真实授权Key验证。

- 指数日线：5个指数，各约275根日线；快照交叉校验收盘值。
- 宽度：沪深300、中证500、中证1000当前成分并集1800只；1797只有效涨跌幅，3只空值不填零。快照仅保留代码、涨跌幅、请求及时间元数据，未发布完整个股行情。
- 情绪：截至日涨停70家、跌停10家、炸板19家，核验完整分页。
- 行业：指定的8个行业观察样本，不称全行业排名。
- 历史：60/120个交易日前的可得价格证据，不回填今日横截面。

证据包含字段、原始输入、来源接口、请求参数、请求ID、数据时点、采集时间、单位、口径、计算公式及支持结论；跨指标计算注明依赖证据。关键结论与条件可点击核验。

置信度按证据可用性、宽度覆盖、时点和冲突评估，高低档不对应收益概率。本版本因估值和事件缺失，正常情况最多为「中」，核心冲突、历史不足或过期时为「低」。

## 已知边界与未做事项

1. 扶摇估值接口支持个股，不将同代码数字的股票估值误用作指数PE/PB；指数估值未接入。
2. 扶摇资讯事件工具限同花顺AI客户端，公开Web未接入；未接入不等于没有事件。
3. 宽度是当前宽基成分集合的截至日横截面；存在成分选择偏差，没有区间历史宽度。
4. 指数成交额是交易活跃度代理，不等于净流入或全A成交额。
5. 上证50/中证1000/创业板指是风格代理；观察阈值为产品规则，未经预测回测。
6. 只开放3个研究指数与20/60交易日区间；未做自由日期、多指数回测、持仓个性化或盘中推送。
7. 模型校验覆盖结构、引用与边界，不能证明所有自然语言归纳均正确；保留证据和不确定项供人工复核。
8. 免费托管不代表外部数据与模型免费。撤销服务端Key后LIVE能力停止，Snapshot和保存回放仍可使用。

## 调用保护

同一研究两分钟内复用结果并标注原始时点；相同并发请求合并。每实例最多同时处理2个研究API任务、每天80个新任务，研究计划与结果各计一次；超限返回429并明确引导案例回放。不同Worker实例分别计数，重启会重置，不能承诺全站费用封顶。案例回放不调用模型；Snapshot新研究仍可能调用模型。
